# Player names in match reports

Show canonical player names instead of jersey references when a confirmed, unique fixture-side athlete mapping exists. Apply this to every AI report section and future import, including user-confirmed source jersey aliases such as #20/#21 → the athlete wearing #28. Do not change source jersey identities in player analytics or event records as part of prose personalization.

1. Re-read the saved or confirmed mapping and verify the athlete's exact same-fixture, same-side lineup row. Keep the same jersey on opposing teams separate. Do not infer identity from an unconfirmed jersey, title, or name similarity.
2. Inventory every explicit jersey mention in each report block: `#19`, `Jersey #19`, `No. 19`, and `number 19`. Resolve the team of each mention from its sentence/clause and source context. A report for PF can discuss P2P players. The report's top-level team is not sufficient. For example, “Their #22 scored once, assisted by #10” refers to two opponent players; never replace that #10 with PF's player. Ambiguous team contexts and unresolved athlete mappings stay numbered.
3. Preserve each exact original source block in `analysis_reports[].source_blocks`. Keep original metadata, headings, bullet order/count, scope, source URL, and AI attribution. In the existing consumer-rendered `blocks`, replace only resolved jersey mention spans with canonical full player names. Preserve every other character, statistic, and claim. Do not regenerate or summarize the report. Keep an `identity_substitutions` array recording source block index, occurrence, original reference, source jersey, resolved team, player name, and athlete slug.
4. Use `${PLUGIN_ROOT}/scripts/report_player_names.py INPUT.json`. Input contains `reports`, `mentions`, and `confirmed_links`. Each mention has `report_id`, `block_index`, `occurrence` (zero-based within the source block), and canonical `team` or null for ambiguity. Each confirmed link has `team`, `jersey_number`, `player_name`, `athlete_slug`, and `lineup_id`. The helper requires context for every detected mention, leaves unresolved/ambiguous references unchanged, rejects conflicting or incomplete mappings, and always derives displayed text from `source_blocks` for repeatable updates.
5. Include the number of substituted and unresolved mentions in the write preview. Validate raw source coverage against `source_blocks` and the separately derived intended display against `blocks`. The completeness manifest can include paths to both. For a deliberate name-resolution update, refresh only `/analysis_reports` in the preservation check and verify all non-name content and unrelated payload fields remain unchanged. Use a guarded narrow payload correction through the shared save function with `p_players = null`; preserve the passing network, shot markers, key events, statistics, player rows, score, and timing.
6. After saving, verify the exact report array and original-source blocks in database readback, then check the ClubATX report displays names. Do not claim all players are named if unresolved opponent references remain. Source text is retained for auditing, not presented as evidence of an unnamed display regression.
