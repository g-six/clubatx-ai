# Efficient collection and persistence

This reference supplements the source-verification and transaction rules. Never change a verified source value to remove a discrepancy, skip a required final replacement preview, or silently modify the approved import when updating this plugin during a run. Apply new projection policies to a new preview and obtain fresh confirmation before changing an already approved dataset.

## Discover context, then ask once per decision set

Resolve relative dates in the user's timezone. Search the current ClubATX project read-only for the date and canonical team pair; a matching stored recording UUID is strong identity evidence. Show a unique fixture candidate with both proposed Veo mappings and the current/proposed official result together. Require explicit confirmation of the displayed set. Do not ask the user to find an ID that the connected database already resolves. Keep confirmations and user corrections in a small decision ledger. An unchanged decision remains confirmed across later previews.

## Capture once and keep a durable audit

Start supported network observation before the exact page reload. Collect only requests initiated by that authenticated match page. Keep the cursor and page through new events. Print a compact inventory of request ID, URL, method, status, content type, and triggering action; do not dump request headers, account responses, tracking requests, or entire response objects into chat. Read candidate bodies based on observed identity and content shape. Endpoint examples are discovery hints only, never permission to guess or fetch endpoints independently.

Use the available host filesystem API to archive verified match-scoped response bodies and rendered evidence locally before normalization. Include original URL, stable match identity, capture context, filters, column inventory, provenance, source conflicts, and a coverage checklist. Store only match analytics and requested evidence, not credentials, cookies, request authorization, or unrelated account data. Archive complete existing database import rows separately before a replacement. Read and compare large JSON locally; return only counts, mismatches, samples, and artifact links to chat. Avoid copying large archives through chat or a sequence of source-code string chunks when direct host file output is available. A local snapshot is an additional audit artifact, not a database backup guarantee.

## Use controls that actually stay open

Prefer semantic browser locators. After each interaction, inspect the fresh rendered state. A modal or dropdown that disappears, or a no-matches result, invalidates the planned locator/index sequence. Stop that sequence immediately. Never fall through into underlying page checkboxes: Veo AI feedback controls can resemble selectable player attributes in accessibility output. Verify the intended dialog title before any attribute click. If the report selector is unreliable, use the recording's read-only Player Stats Overview / View table / Edit columns surface and verify equivalent team and period scope. Use screenshot-grounded coordinates only when the semantic locator does not operate the visible control. Restore the original selected columns, order, team, and period after extraction unless the user explicitly requests a changed view; when asked to enable all player statistics, leave all available columns selected and verify the applied header inventory. Do not rate or regenerate insights.

Keep report modules and player attributes inventoried separately. Capture every available attribute in a full extraction. Read rendered cell arrays with headers and jersey identity rather than parsing concatenated `textContent`; preserve units, missing values, and precision. The detailed physical response may contain individual runs rather than match totals: accept exact playing seconds only from verified aggregate `secondsPlayed` rows, with an explicit total marker and rendered-minute checks. Opponent physical rows do not authorize synthesizing a player table that Veo marks unavailable.

## Preserve source scope and timing

Cross-check team-stat responses against both rendered teams and multiple values, then apply the established source precedence. Preserve precise response percentages even if the UI rounds them. Existing AI narratives may be stale or use different definitions; keep them attributed and separate. Successful pass-location cell counts may sum to fewer than completed passes when locations are unavailable. Disclose that coverage and never redistribute the missing passes. Record whether passes-by-third describes successful or attempted passes; aggregate observed counts only under that same definition.

When explicit nominal duration is absent, confirmed period boundaries plus rendered cumulative clocks may establish it. Record each boundary and duration, the proposed whole-minute half, and multiple second-period source-time/display-minute checks. A near-whole-minute boundary alone is insufficient. Stop timing persistence if those checks cannot resolve the duration unambiguously. Preserve exact period-local seconds and video seconds independently. Never infer nominal duration from the last event.

## Confirm jersey aliases without inventing player totals

A user may identify several detected jerseys as one real player. Resolve the named athlete and unique eligible same-side fixture lineup, then batch-confirm the aliases with all other unresolved identities. Keep an audit mapping from each observed jersey to its confirmed athlete and reported true jersey. Apply that athlete consistently to all matching source events and player rows. Preserve source jersey numbers as source identities; multiple source jersey rows may reference the same confirmed lineup when the live constraints permit it. Do not merge rows, sum distances or seconds, average speeds, or recompute tracked minutes without a separately defined and explicitly confirmed consolidation rule. Preview these source rows separately and verify every saved link. Do not present the alias numbers as additional real players.

## Project complete supported events

Read the live event-type and recipient constraints before building the projection. The original core mapping in `veo-network-events.md` remains the minimum. When the current table supports them and source labels are verified, also project `shot`, `foul`, `corner`, `free_kick`, `goal_kick`, `throw_in`, `loose_ball_recovery`, `kickoff`, `save`, and `offside` using the ordinary confirmed-side/recipient rules and exact video links. Source labels such as `FootballCornerKick` or `loose` require a rendered-label cross-check before mapping. Keep `shot_on_goal` distinct unless the schema has an explicitly verified equivalent; never collapse it merely to satisfy a constraint. Keep possession intervals, target/counterpart events, out-of-play markers, and any unsupported types in the complete source payload and audit, with exact skipped counts and reasons. A live constraint allowing a label does not itself establish its source meaning.

Aggregated duels may carry a nominal source side plus an opponent-event ID or opposing participant attribute. Verify their two-team display and project them as team-neutral once per distinct source record; do not count each participant as a second duel. Preserve the discrepancy when team totals differ. Do not invent a separate assist event from an annotation on a goal without an explicit supported normalization rule; retain the original annotation in the raw audit and preserve independently verified player assists.

## Preview and verify the exact write

Prepare the entire normalized import and atomic SQL before requesting final approval. Link the full preview and player CSV, summarize official score, timing, URL change, player source rows and aliases, graph metrics, source discrepancies, complete feed count, exact deletion/insertion counts, grouped event counts, unknown attribution, skipped records, pre-roll, and final/full-time state. Explicitly disclose removal of manually curated rows. Preserve validated prior payload extensions; never remove them just because a core-only normalizer omits them. Follow spatial-and-complete-data.md and stop on an unexplained extension loss. Refresh confirmation only for changed facts or scope.

Keep SQL under the connector's request limit. Use one explicit transaction and one shared save-function call, with pre-commit assertions of payload equality, complete player values/link pairs, duplicate-preserving event equality, and final state. Guard against concurrent fixture/import changes. After commit, read back the same filtered fixture, payload, all source player rows, and complete event set and compare them with the exact approved local artifact. Never claim success from a successful tool call alone. Preserve the original finalization timestamp and any greater saved live clock.
