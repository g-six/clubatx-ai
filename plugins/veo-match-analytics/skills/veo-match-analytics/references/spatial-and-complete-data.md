# Spatial and complete-data requirements

## Passing network: strictly more than three passes

For every available team passing network, record only connections whose verified source completed-pass count is **greater than 3**, meaning **4 or more**. Exclude counts 0, 1, 2, and exactly 3. Apply this per source connection before persistence, not to line width, opacity, a player's total passes, or the total network. Preserve source direction: A-to-B and B-to-A are separate connections; do not combine their counts to cross the threshold. Do not infer counts from visual thickness or manufacture counts for legacy edges. If counts are unavailable, recapture the observed network response and stop the network write until verified.

Retain the verified average-position nodes needed by qualifying connections. Keep the original complete response in the local audit, alongside excluded-edge counts and the threshold. Distinguish a verified graph with no qualifying edges from unavailable data. Preserve source jerseys and confirmed athlete aliases independently; do not merge source connections merely because jerseys resolve to one athlete.

For the ClubATX consumer, verify the current contract before writing. The established team `passing_network` uses `position_basis: "average_passing_position"`, `direction: "left_to_right"`, `nodes` with `jersey_number`, `x`, `y`, and visual `edges` with `x1`, `y1`, `x2`, `y2`, `width`, `opacity`. Retain `from_jersey`, `to_jersey`, and integer `completed_passes` on each recorded edge for auditable filtering when the consumer accepts them. Coordinates must be finite normalized values in [0,1] and match the rendered direction. Average positions support an illustrative passing replay; they are not measured ball trajectories.

Run `${PLUGIN_ROOT}/scripts/passing_network.py` on the verified normalized graph before preview. Its output filters edges using `completed_passes > 3` and removes unused nodes; it rejects absent or invalid counts. Verify excluded count 3 and included count 4 in the bundled regression checks. This policy changes future captures/previews; it does not silently authorize replacing an earlier confirmed dataset.

## Coverage and preservation gate

Before normalizing, inventory all report modules and all selectable player attributes for each accessible team and period. Track each as captured, unavailable with reason, or pending. For a full import, include passing networks, shot locations/outcomes, and all available individual columns, not just initial visible numeric totals. Display changes must be applied and checked against actual table headers; honor explicit requests to leave every column enabled. Never activate feedback or match editing controls while collecting columns.

Inspect existing payload fields and application consumers before constructing a replacement. Compare existing versus intended keys recursively and account for each optional field. Preserve supported existing extensions such as passing networks and written reports unless refreshed from verified source or explicitly removed by the user. An exact-field core parser must not silently strip these fields. If storage or read paths reject a required field, finish a separately authorized implementation upgrade or disclose the blocker before final import approval. Keeping values only in a local archive is not successful database persistence.

For shot maps preserve each source shot ID, team, source jersey, period, exact match/video seconds, source coordinates, normalized display coordinates, and verified outcome. Check the per-period direction and coordinate transform against rendered markers for both teams. Do not duplicate a goal as both a shot-with-goal-outcome and a separate goal marker. Document the accepted destination contract; retain source evidence and missing-location coverage. Do not replace aggregate team statistics with marker counts.

For player attributes compare the full selector inventory against the saved columns and shared function inputs. Preserve manual metrics exactly, including explicit zeros; do not infer starts or matches. Missing storage capability is a separate upgrade, not permission to omit attributes from a supposedly complete import.

After a narrow correction compare the saved payload with the exact intended JSON and all untouched fields/rows against the baseline. After full import verify graph and shot data through the actual read path. Open the ClubATX fixture's passing sequences, confirm its pitch, and verify Play advances progress. Source feed wire order may be grouped by event type: verify chronology before assigning sequence used by playback; archive original order separately and never claim exact ball movement from average positions.

## Existing Veo AI discoveries and bullet points

A full import must capture every available existing Veo AI card for each accessible team, period, and language, including Overview / What decided the match? and Distribution, Attacking, Defending, and Physical / What stood out?. Preserve individual bullets and headings, source wording, team, module, scope, language, source URL, capture time, source match ID, and AI-generated attribution in the consumer-supported top-level `analysis_reports` array. The established report objects contain `id`, `team`, `text`, `blocks` (`type` and `text`), `period`, `language`, `provider`, `source_url`, `captured_at`, `classification`, `source_match_id`, and `source_revision`. Reuse the current accepted contract rather than inventing a new shape. Preserve original Veo wording in `source_blocks`. In the displayed `blocks`, replace jersey references with confirmed canonical player names only after resolving the mention’s team context. Follow [report-player-names.md](report-player-names.md). Identity substitution must not change statistics, claims, or the source athlete attribution. Keep source/statistical disagreements disclosed rather than editing the source prose.

Never replace `analysis_reports` with an absent or empty field merely because numeric data was recaptured. Back up current reports, compare the available card/bullet inventory with the exact intended payload, and verify each section after readback. Existing verified reports may be restored from the same match's audit after checking the current rendered cards. Do not generate, regenerate, or rate Veo AI analysis for extraction. An unavailable team/card is a disclosed coverage limitation, not an empty replacement for a saved report.

Run `${PLUGIN_ROOT}/scripts/validate_preservation.py BEFORE.json AFTER.json` on payload-only JSON before every replacement preview. It rejects loss or unacknowledged changes of existing optional extensions, including AI reports and team passing networks. A source-verified refresh may be specified with repeated `--refreshed /teams/TEAM/passing_network` or another exact JSON pointer; list its before/after coverage in the preview. This flag is not authorization to remove the field or override a missing-data blocker. After saving, open ClubATX Play-by-Play → Match reports and verify the section headings and bullet points are visible, alongside the passing replay and timeline. Database presence alone is insufficient to claim restored UI.
